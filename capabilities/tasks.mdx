## task

Availability: **external**. [Parameters and responses](/reference/task).

<Accordion title="Tool behavior and constraints">

Actions use same-named params. createAssigned: human-requested task/reminder, including chat requests; explicit dueDate, optional conversationId, assigneeUserId, assignmentNote. No deal: omit conversationId; source links in notes. Date-only: 9 AM owner timezone. Report confirmation.text; never invent placement or confirmed reminder setup. Personal reminders never run agents. dealList: deal tasks/recommendations/assignments. creationOptions: assignees; conversation optional. complete: done. delete: dismissal; draft deletion needs approval. updateDueDate: edit deadline. snooze: owner human-task deadline or native email-response reminder; explicit dueDate. unsnooze: email responses only. start: chat gets seedPrompt; MCP gets deal.handoff instructions/saved prompt, no run/send/apply. Keep recommended; no accept. Never impersonate. applyApproval: requested saved CRM approval; await confirmation, no fallback. Apply all: list scope="#crm-approvals", apply sequentially, report failures. list: own tasks by conversation or scope="#today"/"#overdue"; groups/outputKinds filters; includeRecommended=true for proposals. create: real deal for agentExecutionEnabled; eligible assigneeUserId supported. dueDate="NOW" only without future blockers for non-agent tasks. update: edit/date/execution/done; cleanupDraft=true removes stale draft. Claim completion only for outcome=updated, changed=true, taskStatus=done; blocked is unchanged. cancel: obsolete tasks by IDs/age/conversation; current-run tasks protected. assignmentOptions: ownership/authority/version/pending transfer. reassign: get options; owner/deal-owner/admin only. Needs draft-deletion approval and UUID idempotencyKey; recover pendingTransfer. Finishing is pending. Assignee Slack DM is attempted unless self-assigned/disabled; never notify-user (targets actor). Do not claim delivery without verification.

</Accordion>

### Supported operations

| Operation | Capability | Baseline scope |
| --- | --- | --- |
| `list` | List the caller's tasks by conversation or scope, optionally including recommendations and output groups. | `crm:read` |
| `applyApproval` | Apply an exact saved CRM approval on the user's request and await the CRM result. | `crm:read` |
| `create` | Create a task with supported deal or Task View context; automatic preparation requires a real deal. | `crm:read` |
| `update` | Edit, reschedule or complete a task and optionally remove its stale draft where authorized. | `crm:read` |
| `cancel` | Cancel obsolete tasks by supported ID, age or conversation criteria; current-run tasks are protected. | `crm:read` |
| `assignmentOptions` | Read eligible owners, authority, assignment version and draft-transfer requirements. | `crm:read` |
| `reassign` | Transfer a task with version, authority and idempotency checks; inspect pending transfer state. | `crm:read` |
| `dealList` | Read shared deal tasks, recommendations and assignment context. | `crm:read` |
| `creationOptions` | Discover eligible assignees for a new task, optionally scoped to a conversation. | `crm:read` |
| `createAssigned` | Create an explicitly assigned manual task or personal reminder with a due date. | `crm:read` |
| `complete` | Mark the selected task complete without implying its proposed message was sent. | `crm:read` |
| `delete` | Dismiss or delete a task; deleting a draft requires the relevant authorization. | `crm:read` |
| `start` | Read a preparation handoff externally or prepare context in Cedar chat; no run, send or CRM application. | `crm:read` |
| `updateDueDate` | Change a task's due date through the dedicated date operation. | `crm:read` |
| `snooze` | Snooze an owner human-task deadline or native email-response reminder. | `email:read` |
| `unsnooze` | Remove snoozing from an eligible email-response task. | `email:read` |

### Supported options and filters

Every finite input choice is listed here, including array values and nested variants. Free-text filters, dates, numeric ranges and runtime validation are covered in the [parameter tables](/reference/task#parameters). Options apply to their named operation or branch.

| Input | Choices | Variant / meaning |
| --- | --- | --- |
| `list.scope` | `#today`, `#overdue`, `#crm-approvals`, `#all` | Scope: #all lists all open work user-wide, ignoring ambient conversation/date filters; recommendations default on. Follow nextCursor. For a deal inventory omit scope and set conversationId. #crm-approvals lists open CRM approvals user-wide. #today covers the previous 7 days through today; #overdue is before today without a lower bound. Date scopes use conversationId if supplied, otherwise user-wide. |
| `list.outputKinds[]` | `email`, `slack`, `calendar`, `linkedin`, `whatsapp`, `crm-field`, `crm-opportunity`, `file`, `recommendation`, `none` |  |
| `create.taskChannel` | `email`, `slack`, `linkedin`, `whatsapp` | How this task will be carried out: email, slack, linkedin or whatsapp. Only set it when the channel is genuinely part of the commitment — "reply to this thread" is an email by definition. For open-ended work like "follow up with Sarah", LEAVE IT UNSET: you do not know today whether that follow-up should be an email or a Slack message, and by the time it comes due a channel may exist that does not exist now. An unset channel is decided at execution, with better information; a guessed one is recorded as fact and biases whoever picks the task up. |
| `create.taskType` | `response`, `follow-up`, `post-meeting`, `pre-meeting`, `reactivation`, `manual`, `calendar`, `crm-opportunity`, `field-approval` | Task type. Options: - response: reply to an inbound email - follow-up: outbound follow-up email - post-meeting: post-meeting recap - pre-meeting: pre-meeting prep - reactivation: re-engage a stalled deal - manual: general user-visible task - calendar: calendar invite or placeholder to send - crm-opportunity: create a new deal/opportunity in the external CRM. REQUIRED notes format: include provider (e.g. "hubspot"), accountId if known, instanceUrl if Salesforce, and the full conversation skill's opportunity-creation resource instructions so the chat agent has everything when the user invokes it. - field-approval: proposed field value change pending user approval. REQUIRED notes format: JSON string &#123;"fieldName":"&lt;field&gt;","value":"&lt;value&gt;","fieldLabel":"&lt;label&gt;","conversationId":"&lt;id&gt;"&#125; — this is parsed by applyFieldChange when the user approves. |
| `create.tags[]` | `promised`, `awaiting-them` |  |
| `update.taskType` | `response`, `follow-up`, `post-meeting`, `pre-meeting`, `reactivation`, `manual`, `calendar`, `crm-opportunity`, `field-approval` | Task type. Options: - response: reply to an inbound email - follow-up: outbound follow-up email - post-meeting: post-meeting recap - pre-meeting: pre-meeting prep - reactivation: re-engage a stalled deal - manual: general user-visible task - calendar: calendar invite or placeholder to send - crm-opportunity: create a new deal/opportunity in the external CRM. REQUIRED notes format: include provider (e.g. "hubspot"), accountId if known, instanceUrl if Salesforce, and the full conversation skill's opportunity-creation resource instructions so the chat agent has everything when the user invokes it. - field-approval: proposed field value change pending user approval. REQUIRED notes format: JSON string &#123;"fieldName":"&lt;field&gt;","value":"&lt;value&gt;","fieldLabel":"&lt;label&gt;","conversationId":"&lt;id&gt;"&#125; — this is parsed by applyFieldChange when the user approves. |
| `update.tags[]` | `promised`, `awaiting-them` |  |
| `update.status` | `todo`, `done` | Task status: 'todo' if this is the next task to be completed in this conversation. Use status='done' when the intended task action has already happened. Do not use cancel-task for completed work. |
| `cancel.taskCreatedBy` | `agent`, `user` | When using cancelOlderThan: filter to only tasks created by this actor. Defaults to "agent" so user-created tasks are never accidentally bulk-deleted. |
| `dealList.filter` | `all`, `assignedToMe`, `dealTasks`, `recommendations` |  |
