Agents can produce working artifacts as well as chat responses. Cedar supports editable documents, task-aware agendas, typed tables, HTML reports and diagrams, and documents with explicit workflow buttons. These outputs belong to the agent platform's work cycle: collect evidence, organize it, produce an artifact, review it and keep it current.

Task Views organize what reps need to do; output files hold what the agent produced. An automation can use both, with a task pointing to a researched table, document or deal room. See [the automation layers](/agent-platform/automation-layers).

## Choose an output

| Output | What it supports | MCP and product surface |
| --- | --- | --- |
| Lists and checklists | Research notes, decisions, next steps and ordered procedures | Markdown through `document-write`; use `task` for actual owned work |
| Daily and deal agendas | A task-aware view of personal or conversation work | `document-write` types `agenda` and `conversation_agenda` with task synchronization |
| Tables | Typed columns, stable row IDs, cells, filters/views, sections, bindings and supported enrichment/delegation | The external `table` family; see [complete table capabilities](/capabilities/tables) |
| HTML deal rooms | A designed, shareable account brief, proposal or customer-facing room | `document-write` type `html` and supported document sharing; see [HTML deal rooms](/documents/deal-rooms) |
| Reports and briefs | Narrative findings, charts, source references, samples and recommendations | Markdown or self-contained HTML through `document-write` |
| Flowcharts and diagrams | Process steps, decisions and relationships in a shareable visual output | Self-contained HTML/SVG as an HTML document; use the product graph surface for structured relationship maps |
| Workflow documents | User-clicked actions attached to explanatory content | External document authoring; eligible operation discovery/execution is a Cedar-app workflow surface |
| Org charts and account maps | People, buying roles and relationships with source-backed evidence | [Product graphs](/agent-platform/graphs) for structured relationships, or an HTML diagram for a document output; these are distinct representations |
| Boards and relationship maps | Lanes, records, nodes, edges and views for ongoing work | Product resources; the `board` tool is app-only and there is no external `graph` family |
| Attachments | File-backed artifacts and supported imports | Document attachment metadata and the supported file-request flow |

“List,” “report” and “flowchart” describe the artifact's purpose. They are not extra `document-write` type values. Its exact supported types are `document`, `workflow`, `html`, `agenda`, `conversation_agenda`, `attachment` and `table`.

## Build an artifact workflow

1. Read the evidence and choose a format that fits how the result will be used.
2. Select an authorized destination and inspect an existing artifact before editing it.
3. Write the output with source references, dates and the scope of any analytical claims.
4. Read the result back; verify the actual write or proposal state.
5. Share with the intended audience or reference the file in the consuming agent's instructions.

## Share the result

Use [document sharing](/documents/sharing) for supported document outputs, including HTML. Verify the resulting audience and link; the existence of a saved file is not proof it is published. Structured graphs and other product resources have their own access controls, so do not assume an HTML share operation publishes every output type.

Artifact access, agent resource grants and publication are separate controls. Persisted reports can serve as handoffs between agents; a note in a chat does not configure a future run to read that file.
