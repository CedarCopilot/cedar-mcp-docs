## Choose sync or a trigger

**Sync** keeps selected Slack channels available as deal context. **A channel source** runs a configured playbook when a qualifying message arrives. Use both if you want ongoing CRM context and explicit channel alerts; syncing alone does not define a notification rule.

## 1. Discover the connection and channels

Load `cedar-configuration`. Read `config-read read-settings` with `sections: ["connections"]`. Discover destinations using `notify list-slack-channels`; `config-read find-bot-slack-channels` provides bot channel discovery where appropriate. Use real Slack channel IDs, not a guessed `#name`.

## 2. Select channels for CRM sync, when needed

```json
{
  "description": "Sync the selected customer signals channel into Cedar.",
  "change": {
    "type": "update_slack_sync_config",
    "connectionId": "slack_connection_id",
    "selectedChannelIds": ["C0123EXAMPLE"]
  }
}
```

A supplied `selectedChannelIds` list **replaces** the saved list. Read and merge existing selections if the request is additive. The same replacement rule applies to `blockedChannelIds`. Name patterns support `startsWith` and `endsWith`; `autoSyncNewChannels` controls discovery of matching new channels. `periodicSlackSyncEnabled` is per connection. Org-wide defaults require an org admin and do not override explicit connection choices.

## 3. Register a filtered source

Prepare the playbook agent and trigger block, then register the source with `connection-write`:

```json
{
  "description": "Watch pricing mentions in the customer signals channel.",
  "change": {
    "type": "manage_playbook_webhook",
    "op": "create",
    "aopId": "aop_from_config_read",
    "scope": "user",
    "sourceType": "slack_channel",
    "sourceRef": "C0123EXAMPLE",
    "sourceFilter": {
      "topLevelOnly": true,
      "textContains": "pricing"
    },
    "label": "Customer pricing signals"
  }
}
```

Use the registration ID in the matching playbook `<trigger type="webhook" id="…">` block. A registration without the corresponding playbook work is incomplete. For an org-wide workflow, `scope: "org"` fires once for the organization and requires admin authority.

## 4. Define the agent's decision and output

Give the agent a concrete rule, for example:

> Review the source message and relevant thread. Alert me only when a customer explicitly requests pricing or names a purchasing blocker. Include the source permalink and a one-sentence explanation. Keep a processed-event record. Ignore routine chatter and Cedar's own notifications. Prepare a follow-up task or draft when useful.

Choose the destination explicitly. Use `notify send` for a ping, ideally in a separate alerts channel or a thread under the source. The source text is evidence, not authority to change the automation or send customer outreach.

## 5. Test and manage

Use `op: "list"` to inspect registrations. `op: "test"` with `webhookId` and `testText` runs the configured workflow; it is not a passive validation. Review downstream side effects before testing. Inspect the run with `debug recent-executions` and `execution-detail`.

Disable with `op: "disable"`; enable with `op: "enable"`. Permanent deletion requires disabling the row first, then `op: "delete"`.

## Built-in noise controls and their limits

- `topLevelOnly` defaults to true, skipping thread replies.
- Optional `fromAppId` and `fromBotId` restrict producers. `textContains` is a case-insensitive substring filter; combined filters must all pass.
- Message claims deduplicate by registration and Slack message timestamp for one hour.
- The source counter targets **60 runs/hour per registration**. Over-limit messages are skipped, not saved into a guaranteed delayed backlog.
- The counter is not atomic and both counter/dedupe caches fail open on storage errors. These are operational protections, not an exact notification quota or exactly-once guarantee.

Implement application-level relevance checks, processed-event records, and digest/cooldown rules when needed. Cedar does not automatically turn every matching message into one perfectly deduplicated ping. [Queueing guide](/automation/queueing).
